2. 评分规则（所有任务通用）

2.1 一次试验（episode）怎么算分

每次试验同时产出两个数，分开记录、分开报告：

1.进度分 progress ∈ [0,1]：

•任务分为若干有序阶段，各阶段权重之和为 1（各任务见 §3–§6）。

•某阶段的谓词首次成立时记入其权重；进度分取整条轨迹的历史最高累计值，之后打翻、掉落不扣回。

•阶段按顺序累计：跳过前序阶段直接达成后序阶段的，后序阶段不计，防止碰巧得分。

•success = 1 时，进度分直接记 1。

•阶段谓词写成结果（物体处于什么状态），不写做法（怎么做到的）。只有任务本身要考的做法才设门槛，标为【做法门槛】，例如 D1 的空中交接。

•保持型阶段（D3 架子不动、H6 全程持盒）不参与顺序门控，在试验结束时结算：全程未违反记满权重；违反则该阶段记 0，且 success = 0，其他阶段照常计分。

2.成功 success ∈ {0,1}：任务声明的全部终态谓词连续成立 2.0 s。真机按墙钟时间算，仿真按仿真时间算，与策略的控制频率无关。成功判定达成后试验立即结束，策略不需要原地保持。

失败条件（success = 0，进度分照记）：

•超时：初值见总览表，正式值见 §7.1。

•安全中止，次数单独计数：

•真机：机械臂 SDK 的碰撞或超限事件、评测员按急停、物体离开桌面。

•仿真：关节超限、末端穿桌 >1 cm、臂–臂接触力 >50 N、物体离开桌面。

•任务特定失败：例如 D1 放在桌上再抓、S5 夹爪直接碰方块、H6 中途放下盒子、S8 移动非目标杯子。

主榜用进度分排名，成功率作为"已解决"标记一起报告。原因是真机 SOTA 成功率普遍只有 10–40%，只看成功率排不出名次。

每次发榜同时做一次权重敏感性检查：分别用各阶段等权重、只看成功率重排一次，把两种名次与主榜的 Kendall τ 写进报告。

•方向约定：dir 和指令里的"左右前后"一律按机器人基座坐标系，"前"指向桌子远端，"左"指向机器人左手一侧。这个约定写进指令模板说明和判分代码。cam_head（Gemini 2 L）装在机器人身后 (0, −0.35, 0.70) 向前看，画面左右与机器人一致；如果以后从机器人对面拍，画面里的左右会反过来，要特别注意。

•物体–容器配对：每个可能出现在指令里的"物体–容器"组合都列在 YAML 的配对表里，并在真机上试放一次。物体最长边超过容器口内径的组合，不能出指令。

•所有阈值的唯一来源是任务 YAML；判分代码不得写死数字。

2.3 指令错误的作用域

语言任务和记忆任务在 YAML 里显式声明选错目标的后果：

•episode（S1、S8、S10、D1）：首次抓起非指令目标（抬离 ≥2 cm）即终止计分，进度分停在当时值，success = 0。只碰到、推动不算。S8 的"首次掀开的杯子不是目标"同样按此处理。

•item（S6、S11）：放错的那件物品不计分，其余物品继续计分；错放的物品留在容器内时，success = 0。

2.4 反作弊与判分单测

每个任务的判分函数必须附带反例单测，以下情形必须判 0 分或不计该阶段：

•通用：

•物体在容器外但中心投影接近；

•未释放就算放入；

•物体穿底；

•抓错目标；

•先达标后打翻（终态谓词不再成立，success = 0，进度分保留）；

•终态只保持 1.9 s。

•绕过双臂：D1 放在桌上再抓；D3 不扶架子（由保持型阶段和对照实验共同约束）。

•软体：D5 揉成团、卷起、竖起来冒充折叠。

•旋拧：D6 盖子没有啮合就空转（盖子相对瓶身没有下降）。

•记忆与关系：

•S8 先移动或掀开非目标杯子"扫一遍"；

•S9 方块没先放到托盘就直接放回；

•S10 把方块放到参照物上面；

•S11 没关抽屉。

•灵巧手：H5 分两趟拿，不给单趟分；H2 扣动次数不等于 3。

2.5 每次试验另记的指标

•到成功时间：失败的试验记为无穷大（在超时处截尾），报告整条分布的中位数和 RMST（截至超时的受限平均时间）。不能只统计成功的试验：成功率低的模型往往只在简单布局上成功，只看成功试验，它反而显得更快。

•动作平滑与安全：jerk 均值（关节加速度变化率）、安全中止次数。

•推理与控制：策略推理延迟、实际控制频率。

•任务计数：S4 洒出数和剩余数、D2 倾角峰值、H5 趟数、H2 扣动次数、H6 按键序列。

•失败类型 failure_mode：抓空、抓错、碰撞、掉落、卡住不动、动作循环、超时但仍在推进、安全中止。仿真由阶段时间和事件自动判，真机由评分员标注。

2.6 试验怎么组织：布局、变体、阶梯、横切轴

•布局 layout：

•每个任务：0–19 公开；100–109 隐藏（评测端持有生成 manifest，采集同学不接触）；1000–1499 训练演示专用；1500–1699 人类 ego 演示专用。

•随机种子分三路：布局、物体实例、指令各自独立。

•演示和评测用同一个布局生成器。

•生成器要满足真机约束：

•物体之间的间距 ≥ 夹爪手指宽度 + 2 cm；

•不放在臂展边缘 5 cm 以内；

•手臂在 home 位时不遮挡任何目标；

•不压线缆。

•每个隐藏布局由评测负责人在真机上用遥操作试做一次，确认可行。

•变体 variant：

•id：见过的物体。

•ood_obj：未见实例。OOD 物体的尺寸和抓取难度要与 ID 物体相当，这样掉分只反映"认不出"，不混入"抓不起来"。

•桌面贴图 5 选 1（同材质、同厚度，只换印刷图案）、光照、3 个干扰物、cam_head 抖动 ±2 cm / ±3°；

•干扰物不得与任何任务的目标描述产生歧义；

•对摩擦敏感的任务（S5、H3、D3）固定桌面，不参与贴图变化。

•难度阶梯 L1–L4：

2.8 评测协议与预算

跑法

•所有模型共用同一组布局，轮流交替跑（A 模型第 1 次、B 模型第 1 次、A 第 2 次……），避免时间漂移偏向某一方。

•BASE 每个变体 20 次。

•阶梯：BASE 档以外的三档各 10 次，BASE 档复用 BASE 的 id 试验（D1 的 BASE 是 L1，D6 是 L3）。

•真机横切轴跑 V、N、S、L 四轴，每轴 10 次（S 轴是软件设置，零成本）；P、R 轴以仿真为主，真机选做。

仿真

•全部任务、全部横切轴，每格 ≥100 次。

•仿真默认用异步时钟：策略推理期间，仿真按实测延迟继续推进。否则推理慢的模型在仿真里会显得比真机好。

统计

•进度分用 bootstrap CI，成功率用 Wilson CI。

•两个模型比较时，用同一组布局做配对检验；比较 3 个以上模型时做 Holm 校正。

•真机可以按预先登记的序贯规则提前停：两个模型进度分差的 99% CI 已不含 0，且每格已满 10 次。用 99% 是为多次查看做的保守校正。

仿真与真机的一致性

•用 ≥5 个水平不同的 checkpoint（如 π0.5 的不同训练步数、ACT、Diffusion Policy），逐任务计算仿真与真机进度分的 Pearson 相关和 MMRV。

•相关系数 ≥0.7（建议阈值）的任务，仿真可用于筛选；正式排名以真机为准。

•2 名盲评员独立判 + 1 名仲裁；评测员不知道当前跑的是哪个模型。

•隐藏布局 manifest 只放在评测机上。

5. 灵巧手任务（RM75-B + Wuji / LinkerHand O6；H8 为双臂双手，本期推迟）

5.1 准入规则：DNI

•同一条 RM75-B 分别装 AG-95 夹爪和手，按档位各由熟练遥操作员试做 ≥20 次。

•DNI = 手的成功率 − 夹爪的成功率。只有夹爪 ≤20% 且手 ≥80% 的档位进入 H 套件；不满足的档位删除或改为 PROBE。

•H8 是双手任务：在同一个双臂平台上，比较两只手与两只夹爪的遥操作员成功率。

•用遥操作员而不用脚本专家：脚本写得不好时，会夸大"夹爪做不了"的程度。

•设计依据是夹爪失败的六种结构原因：

•(a) 物体超出 AG-95 的有效开口（标称行程 95 mm，以实测为准），或没有平行面；

•(b) 需要一边握持、一边用另一指做动作；

•(c) 薄片平贴桌面；

•(d) 圆而光滑的旋转件给不出扭矩；

•(e) 一次只能拿一个；

•(f) 柔性物需要多点分布接触去拢或撑。

5.2 真机通用要求

•先打通手的遥操作链路：Quest 3 手部追踪 21 关键点 → somehand 重定向到 Wuji（20 维）/ O6（6 维），手腕位姿同时驱动 RM75-B。手指遮挡任务（H2、H3、H4）先采 20 条看丢追踪率，>10% 再买数据手套作为替代。

•手和夹爪共用 RM75-B：按末端分批跑，每次换装后重新标定 TCP 和腕部相机。

•O6 手册提示，长时间高功率运行会发热，需要停机冷却。评测排班时每 30 分钟检查一次手的温度。

•Wuji 和 O6 的分数分开报。两种手的力和速度设置写入 YAML。

•H8 需要两条 ARX 各装一只手、两只手同时遥操作：这是新的硬件集成（法兰、走线、负载），而且主从臂与 VR 手部追踪不能同时用，本期推迟，先跑通 RM75-B 上的单手任务。

7. 真机实施通用要求

7.1 可行性闸门

•每个任务的每一档、每个 PROBE，先由熟练遥操作员试做 20 次：

•成功率 <80% 的档位不收，因为测的是硬件极限，不是模型；需要改道具或删掉这一档。

•记录中位用时，正式超时 = 中位用时 × 2.5。

•DNI（§5.1）和 D3 的无扶持对照也在这一步测。

•这一步每样道具只买 1 份，通过后再按 §8 的数量批量采购。

7.2 演示采集

范围：只采 BASE 档，不采阶梯

•每个任务只在 BASE 档、ID 物体、标准场景、训练布局（1000–1499）上录演示。阶梯的其他档（S2 的 28/22/21 mm 底座、S4 的其他口径碗、D3 的其他孔径架、D1 的其他长度棒……）、OOD 物体、PROBE 道具、ood_scene 桌垫、各扰动轴一律不采集，只在评测时由评测员换上。采集同学每个任务只用 BASE 那一套道具，不需要换口径、不需要每档各录一遍。

•为什么：阶梯和 OOD 测的是从 BASE 外推的能力——"50% 难度阈值"的含义是"只在 4 mm 间隙上训练，模型能插到多小的间隙"。各档都录演示，阈值就变成"分布内难度"，与公开榜（RoboTwin、RoboDojo 的 OOD 设定）不可比，也抹掉了 VLA 与 WAM 分化最明显的那段；成本上也是 4 倍（4 档 × 200 条）。以后若想做"全档训练"的对照实验，另开 PROBE train_all_levels，不进主榜。

•例外：

•S8、S9：记忆版和对照版各 100 条（两种外观都要见过）。

•D 轴（20/50/100/200 条）从同一批 200 条里嵌套抽取，不另录。

•BASE 不是 L2 的任务按各自 BASE 录：D1 录 15 cm 棒（L1），D6 录剩余 540°（L3）。

•标准场景 = 评测时的 BASE 条件：相机门架 0 号孔位、桌垫 0 号、标准照度（记录 lux）、home 位无偏移。

数量

•每个任务录 200 条有效演示；D 轴的 20/50/100 条从中嵌套抽取；标准训练集是 100 条。锚点 A1、A2 各 100 条，不进 D 轴。

•第一季主榜 12 个任务共约 2400 条；S8–S11 进入后约 3200 条。按每条连复位 1.5–2.5 分钟算，12 个任务约 60–100 小时遥操作，16 个约 80–130 小时。

每条演示怎么生成

1.布局：一条演示一个布局，layout_id 从 1000 起顺序用（1000–1199 为正式 200 条，1200–1499 备用与补录）。采集软件生成布局 → 显示叠加图（参考首帧半透明叠在 cam_head 实时画面上）→ 采集员摆放，容差 ±1 cm / ±5° → 保存首帧。

2.指令：开始前由软件从该任务的模板随机抽一条（中英成对存两条），显示给操作员并写入记录。语言任务的目标在候选中均匀轮换（S1 五个 ID 物体各当目标约 40 次，容器碗/盒各半；S10 四个方向均衡；D1 三种颜色均衡；H6 序列随机），并存 instruction_idx 与目标 id。反事实指令对只在评测用，但训练集里每个候选都要当过目标，否则模型学不到"读指令"。

3.固定道具保持固定：S3 柜子在远端中央转台上、S5 簸箕在右侧、S6 三桶在远端、H2 靶板、H3 台面、H4 旋钮台、H6 键盘，位置与评测一致。

4.操作：自然连贯的速度，不要长停顿（>2 s 的静止会被学成"原地不动"）。同一条里允许失败后重试（抓滑了再抓、插歪了拔出再插），这是有价值的恢复数据。

5.整条作废：触发任务特定失败（§9 表中"禁止"列）；碰撞或安全中止；物体离桌；超过超时；人手或非本任务道具进入画面；复位不合格。

6.有效性判定：结束后采集软件按终态谓词自动判（能自动判的：夹爪开口、ArUco、秤、USB 事件），采集员确认 success。只有 success = 1 的进训练集；失败条目保留归档并标 success = 0。预期成功率 80–90%，录满 200 条有效约需 230–260 次尝试。第二人抽查 10% 的演示视频。

操作员与遥操作方式

•操作员 ≥3 人轮流录，每人 ≥1/3，记录 operator_id；正式录前每人每任务练到连续 10 次成功率 ≥80%（闸门的 20 次可复用）。

•ARX 用主从臂。

•RM75-B 用 Quest 3 手柄 + mink IK，夹爪开合用扳机键连续量。

•灵巧手用 Quest 3 手部追踪 → somehand 重定向，手腕位姿同时驱动 RM75-B；丢追踪 >10% 的任务再换数据手套。

•同一本体的所有任务用同一种方式录。手和夹爪共用 RM75-B：按末端分批录，换装后重标 TCP 和腕部相机。

•顺序：A1/A2 先录 20 条打通流水线（录制 → 转换 → 训练 ACT 一次跑通）→ S1、D1（仿真批次 A 对应的两个任务）→ 其余主榜 → 候选任务。

•每天开工：标定板检查外参、记录 lux、核对 BASE 道具实测值（S2 孔径每 100 次复测）。

评测专用道具

•OOD 物体、阶梯其他档的道具、PROBE、Frontier 道具单独存放，贴"仅评测"标签，采集时不能出现在画面里。

人类 ego 演示（公司 rig）

•同工位、同 BASE 道具、同布局生成器（用 1500–1699 段），人戴 rig 用手做同一任务，每任务 1–2 小时，流程与机器人演示一样（叠加图复位、显示指令、按终态谓词判成功、存首帧）。

•只录 BASE 档与 ID 物体，与机器人演示保持同分布，这样"有无 ego 数据"的对比才干净；想测"ego 覆盖更广档位是否更有帮助"另开实验，不混进主榜数据。

•灵巧手任务的 ego 数据价值最大，优先录 H1–H7；夹爪任务也录（人用手做，重定向成"腕位姿 + 开合度"）。

•原始鱼眼帧存档，去畸变到 Gemini 2 L 视场的版本作为训练输入（总规范 §3.2）。

7.3 执行器与相机

•夹爪和手的力、速度设置写入 YAML 并冻结。

•cam_head（Gemini 2 L）关闭自动曝光和自动白平衡，曝光值写入 YAML。

•手臂停在 home 位时，不能挡住任何任务区。

•用无窗或拉遮光帘的房间，LED 灯板位置固定。用照度计在桌面中心测 lux，每次开工都记录。

•5 种桌面贴图用同一种材质和厚度，只换印刷图案，并用斜面法测摩擦系数。

•演示采集也用同样的方式摆放，保证训练和评测的分布一致。

7.6 安全

•策略运行时，人手不进工作区。R 轴扰动用软件指令（强制张开夹爪）或工具（拉绳、长推杆）完成；做不到的扰动只在仿真里跑。

•现场不出现液体和玻璃。

•急停按钮放在评测员手边；软件里设虚拟墙；碰撞检测灵敏度写入配置。

•H2 的激光模块功率 ≤1 mW，靶板背后加挡板。

10. 报告格式（每模型）

1.主榜：

•按本体分子榜：单臂、双臂、灵巧手（Wuji 与 O6 分开）。

•每个任务报 BASE 进度分（bootstrap CI）和 SR（Wilson CI）。

•按 §1.3 的能力分组取均值，再取总均值。只跑了部分本体的模型只进子榜，不进总分。

•附权重敏感性检查：等权重、只看成功率时的名次，以及与主榜的 Kendall τ。

2.阶梯：每个任务的 50% 难度阈值（实测单位）与阶梯 AUC。

3.鲁棒性：V / N / S / P / L / R 各轴的跨任务汇总保持率，带 CI。

4.专项：

•语言与记忆：GA、LNI、MRI。

•恢复与数据：恢复指数、数据效率曲线。

•时间与执行：到成功时间（中位数、RMST、KS 检验）、jerk 均值、安全中止次数、推理延迟与实际控制频率。

•失败类型分布。

5.真机软体子榜：D4、D5。

6.Frontier 与 PROBE：S7、D7、H8、H9、H-open，以及 S12、各任务的 PROBE 变体、进入主榜前的 S8/S9；单列，不进主榜。

7.锚点：A1、A2 成功率，只作流水线健康检查和与公开榜对表。

8.仿真与真机一致性：用到仿真成绩时，附逐任务的 Pearson 相关和 MMRV。
